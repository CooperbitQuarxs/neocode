# NeoPi menu and control-plane inventory

Source snapshot: NeoPi nightly [`4443cfc03814`](https://github.com/PsychedelicShayna/neopi/commit/4443cfc03814963b3ebdf85ace1db37afa5f9b2a), inspected on 2026-10-20. This is the factual inventory for [NeoCode #49](https://github.com/PsychedelicShayna/neocode/issues/49). The GUI conversion mechanism remains undecided; this document specifies no renderer or replacement state model.

## Scope and reading the tables

The [builtin registry](https://github.com/PsychedelicShayna/neopi/blob/4443cfc03814963b3ebdf85ace1db37afa5f9b2a/packages/coding-agent/src/slash-commands/builtin-registry.ts#L43-L60) contains 98 canonical commands and eight aliases. The tables cover every registry entry, the settings surfaces declared in `modes/settings.ts`, and their existing public RPC/control equivalents. Dynamic extensions, file commands, skills and MCP prompts are described separately.

RPC means the typed JSON-line session protocol. Control means the local control socket, including its TUI presenter. “No dedicated command” means no corresponding operation in the inspected public command unions; it does not mean the underlying operation is impossible through tools or local slash input. Generic command execution is not a structured menu/configuration API.

Sources: [RPC commands](https://github.com/PsychedelicShayna/neopi/blob/4443cfc03814963b3ebdf85ace1db37afa5f9b2a/packages/coding-agent/src/modes/rpc/rpc-types.ts#L41-L160), [control commands](https://github.com/PsychedelicShayna/neopi/blob/4443cfc03814963b3ebdf85ace1db37afa5f9b2a/packages/coding-agent/src/control/types.ts#L210-L323), [RPC handlers](https://github.com/PsychedelicShayna/neopi/blob/4443cfc03814963b3ebdf85ace1db37afa5f9b2a/packages/coding-agent/src/modes/rpc/rpc-mode.ts#L1482), and [control handlers](https://github.com/PsychedelicShayna/neopi/blob/4443cfc03814963b3ebdf85ace1db37afa5f9b2a/packages/coding-agent/src/control/host.ts). Control `slash/input/action/keys` requires a TUI presenter; a headless host can return `no_tui`. A slash command marked TUI-only can still have a separate structured RPC equivalent.

Persistence terminology: **session** is runtime state unless a session-file write is named; **settings** is the layered registry; **agent directory** holds persona/loadout/package definitions; **process** denotes a local process or OS operation. In the UI column, **Dual** means both a generic slash handler and a TUI handler, not automatic RPC parity. **Handle only** is a generic handler adapted by the TUI.

## Settings panel and persistence

The [TUI settings declarations](https://github.com/PsychedelicShayna/neopi/blob/4443cfc03814963b3ebdf85ace1db37afa5f9b2a/packages/coding-agent/src/modes/settings.ts) define the groups below. Each row lists exact setting IDs, not a second list of commands. The panel reads layered values and writes/unsets global values through its settings host. Control can address these registered IDs with `settings_get/set/unset`; no RPC operation exports this panel’s groups, conditions, labels or option metadata. Theme/composer options can be runtime-derived, and image/macOS-specific controls have visibility conditions.

## State, configuration and event coverage

### Session state and dialogs

`get_state` uses the shared [session-state builder](https://github.com/PsychedelicShayna/neopi/blob/4443cfc03814963b3ebdf85ace1db37afa5f9b2a/packages/coding-agent/src/modes/rpc/rpc-session-state.ts#L61-L110). It reports model, thinking level, streaming/compaction/settlement, queue contents and modes, session identity, context usage, todos, active role, chat/plan/goal state, fast/slow mode and usage data. Optional dump data includes system prompt and tools. Control snapshots add TUI view/focus/overlays, dialogs, connection state and approval state; they do not request the dump.

RPC supplies session-info/config/mode updates and settled/queue events. Extension UI requests cover selection, confirmation, editor/ask input, notifications, status/widgets/title, editor text and opening URLs; responses answer those requests. Plan and tool-approval requests have response/cancel frames. Control `dialogs/dialog_answer` exposes active dialog summaries and answers. These interactions do not export every local menu as a persistent configuration object.

### Model roles and mixtures

`get_roles` returns role IDs, aliases, names, sections, configured patterns and resolved models/thinking levels; `set_role` selects one. Model listing/selection/cycling and thinking-level listing/selection/cycling are separate typed operations. [Role result shape](https://github.com/PsychedelicShayna/neopi/blob/4443cfc03814963b3ebdf85ace1db37afa5f9b2a/packages/coding-agent/src/modes/rpc/rpc-roles.ts#L37-L55); [model/role handlers](https://github.com/PsychedelicShayna/neopi/blob/4443cfc03814963b3ebdf85ace1db37afa5f9b2a/packages/coding-agent/src/modes/rpc/rpc-mode.ts#L2055-L2186).

Role configuration is a registered `modelRoles` record with a `modelRoleStorage` scope choice, writable through control’s member-setting path. Selecting a role is not editing its definition. Mixtures expose list/create/select, including project/user creation scope; update/delete and the full mixture editor are not separate public commands. Loadout overlays remain a different local facility.

### Advisors, agents and rules

Advisor settings exposed through the registry are `advisor.enabled`, `advisor.syncBacklog`, `advisor.reviewMode`, `advisor.reviewInterval`, `advisor.maxNotesPerUpdate` and `advisor.evictStaleResults`. RPC/ACP protocol defaults affect their effective defaults. Advisor message/cost/yield events are emitted; no dedicated advisor-definition or configuration-editor CRUD command is present.

RPC subagent APIs list agents, read messages, steer/cancel and select subscription detail. Lifecycle/progress/event frames carry updates. Control `agents` adds send/wait/inbox/kill/revive/describe/focus/unfocus; monitor operations provide grants, transcripts, subscriptions and chat where supported. Advisor monitors are read-only. These are runtime-agent operations, not a definition catalog for the TUI Agent Hub.

TTSR rules have settings and extension-dashboard surfaces, but no builtin `/rules` command or dedicated rules-inventory RPC. `/status` is the alias of `/extensions`, not a general status command. `/omfg` is a rule-authoring workflow, not a rules configuration API.

### Persona, loadout and eval

Persona definitions live in `neopi-persona.json`; loadouts and their active marker live in `neopi-loadout.json` under the agent directory. Persona selection affects session prompt state; loadout application installs runtime model-role overlays and requires an idle session. Live voice personas are separate from ordinary system-prompt personas. Neither has dedicated public RPC CRUD.

`/repl` changes the local composer target among agent/JS/Python/bash. Control `repl_execute` executes eval code; it does not expose that composer menu or a kernel catalog. The local kernel status/reset/interrupt surface is not a structured RPC kernel lifecycle API. Bash execution and abortion are separately exposed.

### Discovery and capabilities

Session switching, opening, new sessions, branches, forks, history/tree/messages, naming, stats, HTML export and compact-in-place handoff have typed operations. The CLI catalog and session lease/history-identity capabilities support discovery and ownership; `get_state` alone is not a catalog. [Ready capabilities](https://github.com/PsychedelicShayna/neopi/blob/4443cfc03814963b3ebdf85ace1db37afa5f9b2a/packages/coding-agent/src/modes/rpc/rpc-capabilities.ts#L12-L25) advertise `get_usage`, `get_roles`, `set_chat_mode`, `tool_approval_request`, `set_mode`, `new_session`, `session_lease`, `plan_proposal_cancel`, `prompt_entry_ids`, `session_catalog`, `session_history_identity` and `control_pipe`.

## Dynamic commands and local-only presentation

The [available-command builder](https://github.com/PsychedelicShayna/neopi/blob/4443cfc03814963b3ebdf85ace1db37afa5f9b2a/packages/coding-agent/src/slash-commands/available-commands.ts#L33-L110) adds loaded skill commands, extension commands, custom commands, MCP prompts and file commands. Their names depend on the environment and are not a finite builtin inventory. RPC `get_available_commands` and available-command updates expose the current command list. Skill invocations are distinct from `/skills` package management.

ACP’s builtin command list includes generic handlers, not TUI-only handlers. Its reserved names include aliases of those generic builtins. In a collab guest, the builtin allowlist includes dump, export, copy, open, hotkeys, settings, leave, collab, exit and quit; the remaining host-side commands are restricted.

The model/agent/extension hubs, settings/status-line editors, persona/loadout/chain/mixture editors, hotkey sheet, session/tree/thinking/copy selectors, IRC viewer and debug tools retain local presentation state. Generic control input can drive a running TUI, but the inspected contracts contain no shared menu-schema export for those surfaces.
